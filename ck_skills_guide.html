ck-skills Quick Reference

What each skill does, when to reach for it, exactly what to type to invoke it, and what it needs before it'll run. One tab per skill.

Getting access

Two different needs, two different paths — installing the repo so Claude Code can actually run these skills, or just reading how one works without setting anything up.

Path A — just want to read a skill (no install)

Every skill is a plain markdown file on GitHub — open it in a browser, no clone, no Claude Code, no credentials:

# Browse any skill directly https://github.com/carla-klaasen-digitad/ck-skills/tree/main/.claude/commands/{skill-name}

Good enough for checking exactly what a skill does or how it's invoked before deciding whether to run it yourself.

Path B — install it so Claude Code can run the skills

1

Have Claude Code installed

If you don't already have it, follow Anthropic's install instructions at docs.claude.com/en/docs/claude-code.

2

Clone the repo

Works from any location on your machine — nothing inside the repo depends on a specific folder path.

3

Launch Claude Code from the repo root — this step is not optional

Skills are loaded from .claude/commands/ relative to whatever folder Claude Code is opened in. Open it from a parent folder, or any other folder, and none of these skills will load at all — silently, with no error.

4

Add a .env file at the repo root

Most skills need Google OAuth credentials and/or an Anthropic API key here. There's no template checked into git — copy an existing .env from a machine that already has one, or ask Carla for the values. Never commit this file; it's already gitignored.

# Step 2 git clone git@github.com:carla-klaasen-digitad/ck-skills.git cd ck-skills # Step 3 — from inside that same folder claude
⚑

Wrong working directory is the #1 "why isn't this skill working" cause. If Claude Code was launched from your home folder or Desktop instead of from inside ck-skills/, every slash command in this guide will fail to trigger, with nothing telling you why. If a skill seems to not exist, check this first before anything else.

What it does

Loads the correct brand's writing guidelines the moment a brand name appears in a content task — silently, before you write anything. Also loads the market-appropriate legal file (on-site vs. off-site, USA vs. Canada).

When to use it

It's automatic — you don't invoke it. It fires on any content task (writing, briefing, review) that names a brand from the registry: Activia, Oikos, Silk, International Delight, Danimals, Evian, and 15+ others. Use the slash form only when you want to force a fresh read or check what's registered.

How to invoke

/brand-context Silk → force-reload Silk's file /brand-context → list all registered brands

Setup requirements

A guidelines file must exist at shared/brand-guidelines/{brand}.md — nothing else to configure.

Watch out for

⚑

"Two Good" vs. "Too Good" — Canada's "Two Good Yogurt" (80% less sugar) and USA's "Too Good & Co." (60% less sugar, different product line) may be two distinct real brands historically conflated in this registry. If "Two Good" comes up, the skill is supposed to flag it and ask before treating it as Too Good & Co. — don't let it silently assume.

What it does

Turns a Digitad SEO audit spreadsheet into a client-facing "technical recommendations" Google Doc for the client's dev team — one doc per brand per quarter, built from a list of issues you name.

When to use it

Any Danone USA brand + "technical recommendations" or "dev team report" or a report type (Indexation, Canonical/404/301, Meta-tags, Structured Data, Performance, Images, Links, About Page).

How to invoke

"Write the dev team report for Dannon — cover Sitemap.xml, Robots.txt, and Canonical/404 issues."

Setup requirements

Google OAuth2 in .env — Docs, Sheets, and Drive (drive.file) scopes
The brand's audit spreadsheet ID registered in CLIENT-REGISTRY.md
Reference write script: write_activia_doc.py

What happens

Looks up the brand's audit sheet automatically → maps your issue list to audit rows → asks 3–4 clarifying questions (scope, supplementary docs, technical depth) → writes the doc via the Google Docs API directly (three-part Problem/Impact/Fix structure per section) → writes the doc link back into the production plan.

Watch out for

i

Style rules are brand-specific and easy to violate by habit — no links in Light+Fit/Happy Family reports, under 3 em-dashes per document, never name a specific tool/plugin/vendor in a fix, and every sitemap/indexation section needs a "Sitemap Maintenance Guidelines" bullet list. Full list in STYLE-RULES.md.

What it does

Builds a prioritized on-page content production plan for a brand from a keyword research sheet — category pages first, then product pages, then discovery content (recipes, blog) — and writes it directly into the production plan sheet.

When to use it

"Build the production plan", "fill the content strategy", "on-page strategy" — when you have a keyword research sheet ready and need it turned into a prioritized, word-budgeted plan.

Setup requirements

Four inputs up front: a brand brief, the production plan sheet URL + a specific row range you're allowed to write to, the keyword research sheet URL, and a total word count budget
SE Ranking MCP auth (for filling gaps when a priority keyword isn't in the research sheet)
The service account content-bot@content-automation-492519.iam.gserviceaccount.com needs edit access to both sheets

What happens

Filters out branded/utility/off-catalog keywords → classifies each page into Category/Product/Discovery tiers by URL + intent → checks every claim-implying keyword ("probiotic", "organic", "low sugar") against the brand's actual approved claims → flags cannibalization risk between rows targeting the same keyword → presents the full plan for your explicit "confirm" before writing anything.

Watch out for

⚑

Calls /global-seo-skill whenever it hits genuine SEO ambiguity (intent classification, cannibalization, an unfillable word budget) rather than guessing — if you see it pause and consult that skill mid-run, that's by design, not a stall.

What it does

Builds a complete 404/redirect-chain/canonical-issue redirect plan: takes a broken-URLs export and a live-URLs export, finds the best redirect target for each broken URL through a 6-tier matching pipeline, validates every target actually resolves live via HTTP, and delivers a formatted Google Sheet.

When to use it

Standalone — "build a redirect plan", "fix 404s", "redirect mapping". Also called automatically by seo-geo-technical-audit right after it scores 404s, redirect chains, and canonical issues — no separate invocation needed there.

How to invoke

/redirection-plan-skill (then provide: a broken-URLs file — Screaming Frog 4xx export or GSC Coverage "Not found" — and a live-URLs file — Screaming Frog 200-status export or a sitemap)

What happens

Classifies each broken URL's issue type and action (301 redirect / flatten chain / block via robots.txt / soft-404 / no action) → for real 301 candidates, matches against live URLs tier by tier — exact path → chain resolution → keyword overlap → semantic → parent category → homepage fallback, stopping at the first solid match → validates every proposed target actually returns 200 via curl → assigns High/Medium/Low priority by inbound links → writes the Google Sheet.

Watch out for

i

Cross-type matches are blocked by design — a broken yogurt URL will never get redirected to an ice-cream page, even if the slugs look similar. A correct fallback (to a parent category, or the homepage) beats a plausible-but-wrong specific match every time.

What it does

Three things in one skill: translate a source-language page to English, create a new English page from a brief, or push content you've already written into a Google Doc output template — all via a generated Python push script.

How to invoke

Paste a structured block — pick the mode that matches what you're doing:

TRANSLATE PAGE --- source_doc: <Google Doc URL> source_language: French output_doc: <Google Doc URL> website: <client website URL> primary_keyword: <exact primary keyword> meta_title: <exact meta title text> word_count: <target number> ---

CREATE PAGE and PUSH CONTENT modes follow the same pattern with different fields — see the skill's SKILL.md for the exact block format of each.

Setup requirements

Hard dependency on the local content_automation/ folder — push_content_to_gdoc.py, its venv/, and token.json.This folder is intentionally excluded from ck-skills git (it's not portable — OAuth tokens, a full venv) and must already exist on the machine running this skill. It's not something a fresh clone of this repo gives you.

Watch out for

⚑

The generated push script has a real footgun: any body text containing an apostrophe must use double-quoted Python strings, or the script throws a SyntaxError before it ever touches the doc. HttpError 403 means the OAuth token in content_automation/token.json needs re-authing.
