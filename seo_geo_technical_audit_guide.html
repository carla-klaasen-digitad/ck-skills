SEO/GEO Technical Audit Guide

The most heavily-specified skill in the repo: 123 scored elements across 6 phases, a mandatory data-intake gate, a two-script workbook pipeline, and a client-facing HTML report. This is what actually happens under the hood, and what to watch for at each stage.

What this is

A full technical SEO + GEO (generative-engine visibility) audit, scored element by element against a fixed rubric, ending in a Google Sheet workbook and a 9-file client-facing HTML report. It never fabricates a score — every element is either scored from real data or explicitly marked DATA MISSING.

The scoring engine, in plain terms

Rating scale

Not Present (1) → Weak (2) → Medium (3) → High (4) → Excellent (5), or Not Applicable. Codes like "W" or "H" are internal shorthand only — every output file spells the full name.

Weight tiers

Critical (10) → High (7.5) → Medium (5) → Low (2.5) — how much a given element actually matters for this site.

Priority Score

Rating × Weight, lower = more urgent. ≤10 is High priority, 11–20 Medium, 21–35 Low, 36–50 Monitor. This is formula-driven in the sheet — never hand-written.

Phase breakdown

Technical (27) · UX (14) · Tools & Config (10) · On-Site SEO (25) · Off-Site (11) · GEO/AI Visibility (36) = 123 elements total.

DATA MISSING vs. PROMPT USER — the difference matters

These look similar but trigger opposite behavior:

DATA MISSING

A required export was already declared absent during intake. Mark it, state which file is needed, keep moving — no interruption. You already said you don't have it.

PROMPT USER

The element needs a manual visual check, admin access, or a judgment call that's cheaper for you to answer than for Claude to infer. Stops and asks the exact question from the reference file — never paraphrased.

Before scoring starts — Phase 0 intake

This is the single longest phase and it exists for a reason: every later phase assumes the intake was done right. Skipping ahead produces silently under-scored elements.

1

Session init

Runs init_session.py to test every API connection at once (Screaming Frog, SE Ranking, Drive, PSI, GSC, GA4, Moz, WHOIS) and confirm client name, site URL, and Drive folder access. Required whenever the workbook will be a Google Sheet, or any source is API-fetched.

2

Site context + writing style

Collects website, site type, industry, market before anything else. Then shows one finding in three tones (technical / plain-language client-facing / executive-brief) and asks which to use for the rest of the audit — plain-language is the default if you don't weigh in.

3

Workbook format

Google Sheet (shareable, live) or a local .xlsx. Choosing Sheet triggers a Drive validation check before Phase 1 can begin.

4

GSC access check — before anything else is asked

Checks whether Claude already has direct GSC/GA4 MCP access to the site. If it does, Coverage/Performance/Core Web Vitals are auto-fetched — no export needed for those. If not, every one of them becomes a manual ask.

5

Screaming Frog — internal crawl or manual exports?

If run internally via the SF REST API, it also checks which integrations (GA4, GSC, PSI, Majestic/Moz) are active in that config — those become auto-fetched sources too, not separate manual exports.

6

Full data-source inventory

A complete table of every possible source, what it unlocks, and how it's fetched (API / SF / Manual). Nothing gets scored without a row in this table being resolved one way or another.

7

Gap report — before any scoring

States plainly: confirmed sources, missing sources, and exactly what % of the 123 elements can actually be scored right now. You explicitly confirm before Phase 1 starts.

8

Production Plan created

A live tracked list of every anticipated output file (workbook, HTML report, redirect plan, sitemap delta, etc.) with status markers — not optional, not skippable.

i

GSC Coverage always outranks Screaming Frog for indexation, 404s, redirect chains, and canonical tags. SF only finds URLs reachable from the current internal link graph; GSC finds URLs from every source — old sitemaps, backlinks, historical crawls. If GSC data arrives after an SF-only score was already written, that element gets rescored from GSC.

Session close — the sequence after Phase 6

This is the longest stretch of the whole audit and the one most likely to get rushed. Every step below is a named, non-skippable gate — not a suggestion.

1

Executive Summary + Session Log

Written as .md files before the workbook — these summarize findings and the full session record.

2

Conditional deliverables review

A checklist of what was generated this session vs. what was triggered but not yet built vs. what's still awaiting your confirmation — surfaced before the workbook, not after.

3

Workbook — the two-script pipeline

extract_data.py parses every phase .md file into workbook_data.json, then generate_gsheet.py reads that JSON and creates the actual Google Sheet. Audit data is never hand-typed as Python literals — that approach silently fails past ~50 rows.

4

Comments for Claude feedback loop

You open the finished sheet, write notes into column R for any row you want revisited, then say "comments added." Claude reads every non-empty R cell, classifies each as a row fix / a skill-level rule / both, applies the fix, and clears that cell — one at a time, never in bulk, and never before the fix is actually confirmed written.

5

HTML client report

Built in one pass by scripts/generate_html.py reading workbook_data.json — never written file-by-file by hand. Hand-writing these individually bypasses the design system entirely and is explicitly disallowed.

6

Activity log

activity_log.py auto-searches your local Claude session JSONLs for this audit's session ID and generates the final activity record.

Rules that exist because something already broke

Column M is formula-only

Priority is calculated automatically from Score × Weight. Any hardcoded text written to that column silently inverts the displayed priority — an Excellent score can end up showing as High priority.

No property IDs, ever

GA4 property IDs, GSC property IDs, OAuth tokens — none of these may appear in any cell, in any column. Use the descriptive name only ("GA4 — Dannon," never "GA4 property 377536711").

No element codes in client-facing cells

T01, G17, U04 and similar are internal notation only. A client reading the report has no idea what they mean and shouldn't have to.

FAQPage schema is never recommended

Deprecated by Google. This has had to be corrected more than once across different brands' audits — treat it as a hard no, not a case-by-case judgment call.

How to Correct never names a product

Describe the action, not the vendor: "convert images to WebP" rather than naming a specific CMS or plugin that does it.

Contradiction detection is a hard stop

If a later phase's data contradicts an earlier PROMPT USER answer, scoring halts on that element until you explicitly resolve which one is right — it's never silently overwritten either way.

A — New AuditDefault. Full 6-phase run from Phase 0.

C — Schema Deep-DiveOnly the schema markup analysis — skips straight to that sub-phase.

What to say to Claude

Starting a new audit
"Run a technical SEO and GEO audit for [Brand] — [website URL]."
Claude will run Phase 0 intake and ask which operating mode, then walk through data-source collection with you before scoring anything.
You only have some of the data right now
"I don't have GA4 or backlink data yet — just Screaming Frog and GSC."
Fine — the gap report will mark the affected elements DATA MISSING and tell you exactly what % of the audit that leaves scoreable. Nothing blocks on this.
Reviewing the finished workbook
"I've added comments in column R — comments added."
Triggers the feedback loop: each comment gets classified, the right reference file gets loaded, the fix gets applied, then that cell clears.
Something in the sheet looks structurally wrong
"Column M shows 'High' for a row that scored Excellent — is that right?"
It isn't — that's the formula-override bug this guide flags above. Worth reporting immediately rather than assuming the sheet is right.
